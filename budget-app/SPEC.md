## 1. 개편 목표 요약

현재 v1은 `2026-05` 단일 월 + 하드코딩 `BUDGET` 상수 + localStorage 기반의 정적 프로토타입입니다.
v2는 **월별로 동작하는 진짜 가계부**로 전환합니다. 핵심 축 3가지:

1. **월별 가계부화** — 모든 화면(홈/입력/리포트/챌린지)이 선택된 "현재 월"을 기준으로 동작. 월 전환 시 전체 카테고리/데이터 자동 갱신. 단 복리(누적 저축·투자)는 월이 넘어가도 이어서 누적.
2. **전면 편집 가능화** — 수입·고정지출·저축/투자·기타지출·용돈 등 **모든 항목**을 추가/수정/삭제 가능. 하드코딩 상수 제거.
3. **기기 간 동기화** — localStorage 단독 → **Supabase 백엔드** + 오프라인 우선 동기화. 로그인 없이 기기별 동기화 키로 두 사람이 같은 가계부 공유.

## 3. 데이터 모델

### 3.1 설계 원칙
- 모든 금액 항목은 **월별 레코드**로 저장(`month: 'YYYY-MM'`). 하드코딩 `BUDGET` 상수 제거.
- 항목은 공통 형태로 통일: `{ id, label, amount, owner, category, note }`
  - `owner`: `'이현' | '혜원' | '공동'`
  - 고정지출은 추가로 `구분`(차량/보험/통신/구독/생활/공과금/교통/저축 등 — 시트의 "구분" 컬럼)
- **삭제는 soft하게**: 슬라이드 삭제 시 해당 월 레코드에서만 제거(과거 월 기록 보존).

## 6. 동기화 아키텍처

```
[입력/수정]
   → localStorage 즉시 반영 (오프라인 우선, D3)
   → 온라인이면 Supabase upsert (updated_at 갱신)
   → 온라인 복귀 시 큐에 쌓인 변경 일괄 동기화

[충돌] 같은 레코드를 두 기기가 수정
   → updated_at 더 최신인 쪽 채택 (Last-Write-Wins, D4)

[기기 페어링] 로그인 없음 (D2)
   → 기기 A가 sync_key 생성 → 기기 B가 입력 → 같은 household 구독
   → Supabase Realtime으로 변경 푸시(선택)
```

복리/누적(D5): `savings_ledger`에 월별 저축·투자·비상·이월금 기록. 앱 시작월(`created_month`)부터 순차 누적. 월 전환 시 전월 잔여금이 다음 달 이월금으로 더해짐.

## 10. 구현 우선순위 (제안)
1. 데이터 모델 월별화 + 전월 복사 + 자동 저장 (홈/입력 동작 기반)
2. 전체 항목 편집화(인라인 아코디언 + 슬라이드 삭제 + 항목 추가) + 명칭 변경
3. 보텀시트 모달 + 저축/투자 복리 누적
4. 리포트 개편(고정+기타, 개인별, 달성률)
5. 52주 챌린지 신규
6. Supabase 연동 + 기기 동기화 + 오프라인 큐
7. 시트 시드 마이그레이션

> 1~4는 클라이언트 단독으로 완결 가능(localStorage). 6은 그 위에 동기화 레이어로 얹음.
