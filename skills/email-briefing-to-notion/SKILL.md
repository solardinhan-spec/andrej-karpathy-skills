## 0. 실행 시각 확인 (KST 기준)

루틴 시작 시 **가장 먼저** 현재 KST 시각을 확인한다.

```bash
TZ='Asia/Seoul' date
# → 예: Fri May 29 08:39:30 KST 2026
```

확인한 날짜·시각·요일을 기준으로 아래 분기를 따른다.

| 요일 | 실행 조건 |
|------|-----------|
| 화·수·목·금 | 평일 루틴 (Step 1 → 6) |
| **월요일** | **① 일일 브리핑** (주말 포함 조회) + **② 주간 요약 브리핑** (Step 7) |
| 토·일 | 실행하지 않음 (조용히 종료) |

### 월요일 — 두 가지 실행 조건

#### ① 일일 브리핑 (주말 포함)
- Step 1 ~ 6을 그대로 실행하되, **이메일 조회 범위만 다르게** 적용
- 조회 범위: **전주 금요일 06:30 KST ~ 월요일 당일 06:30 KST**
- Gmail 검색 쿼리 예시 (월요일 2026-05-25 기준):
  ```
  in:inbox -is:spam -in:draft -in:sent -label:[Notion]
  after:2026/05/22 before:2026/05/25
  ```
- 페이지 제목: `YYYY.MM.DD (월)` — 월요일 날짜 기준

#### ② 주간 요약 브리핑
- Step 1 ~ 6 완료 후 **추가로** Step 7을 실행한다
- 전주 월~금 Notion 이메일 브리핑 페이지를 읽고 한 주 요약 페이지 생성

---

## 1. 중복 확인

Notion 상위 페이지 하위에 `today_` 제목 페이지가 이미 존재하면:
- 새 페이지를 만들지 않는다
- Gmail에서 `[Notion]` 레이블 미부착 이메일만 추가 수집
- 기존 페이지 하단에 `--- 추가 브리핑 (HH:MM ) ---` 섹션으로 append
- 전날 노션 페이지를 확인하여 이어지는 내용이 있으면 연관 표시를 한다.

존재하지 않으면 Step 2로 진행.

## 2. Gmail 이메일 수집

### 검색 쿼리
```
in:inbox -is:spam -in:draft -in:sent -label:[Notion]
after:yesterday_ before:today_
```
- pageSize: 50
- `-label:[Notion]` = 이미 처리된 이메일 제외

### 조회 전략 (토큰 절약)
1. `search_threads` — 제목·발신자·스니펫 전체 수집
2. 스니펫+제목으로 1차 분류 (Step 3)
3. **P1·P2만** `get_thread`로 본문 전체 조회
4. P3·P4는 스니펫+제목으로만 요약

### 컨텍스트 초과 시
P1 → P2 → P3 → P4 순으로 우선 처리하고, Notion 페이지 최상단에 표기:
```
⚠️ 컨텍스트 제한 — 총 N건 중 M건만 처리됨
```

## 3. 이메일 분류

모호한 경우 더 높은 우선순위로 분류한다.

### 🔴 P1 — 긴급 사항 (Critical)
- TO에 `han@solardin.com`, `한이현` 직접 포함
- 키워드: 요청, 확인 부탁, 검토 부탁, 긴급, 승인, 마감, 결정, 회신 요청, 한이현, 기구설계팀
- 예외: 전체 공지사항
- 4M 변경 승인, 결재 요청 문서

> 예: `MPT 파트리스트 수정 요청 건` / `Amkor Technology 긴급 Swap 출하 요청` / `4M 변경 승인 요청서`

### 🟠 P2 — 중요 사항 (High)
- 현장 장비 알람·이슈 (chiller 고장, OCR Alarm 등) — 모니터링·대응 필요
- 결재 취소·반려 알림 중 재처리 필요한 것 (`_sysmaster_` 발신)
- 외주업체 납기·일정 답변 필요 건
- D-0 ~ D-1 마감

> 예: `(260525_MMJ) Comp2 inner check alarm 발생` / `[결재취소] 한이현` / `파카코리아 솔밸브 전압 마킹 답변`

### 🟡 P3 — 일반 사항 (Medium)
- 프로젝트 진행 상황·CC 참조 업무
- 현장 일일보고 중 이슈 있는 것
- 납품대장, 납기 조율, 출하 진행 상황
- 기한 있는 관리·공지 (법정의무교육 등)

> 예: `칠러납품대장_260522` / `601 공냉식 피팅 확인 요청` / `법정의무교육 기한 임박`

### 🟢 P4 — 일반 사항 (Low)
- 현장 일일보고 `(YYMMDD_현장코드)` 중 특이사항 없음·완료 보고
- 이슈 없는 일일회의록·주간업무보고
- 결재 완료 알림, 경조사·사내공지

> 예: `(260525_MMS) 특이사항 없음` / `주간업무보고 5월 3주차_정예진`

### ❌ 제외 (레이블 미부착)
업무 무관 외부 서비스: Zapier(`learn@send.zapier.com`), Slack(`no-reply@email.slackhq.com`), make.com, n8n, GamsGo, Google 보안알림(`no-reply@accounts.google.com`) 등

## 7. 주간 요약 브리핑 (월요일 전용)

> Step 6 완료 후에만 실행. 월요일이 아닌 경우 이 단계는 건너뛴다.

### 7-1. 주차(週次) 계산

현재 월요일이 해당 월의 몇 번째 월요일인지 계산한다.

```
N주차 = 해당 월에서 현재 월요일이 몇 번째 월요일인지
예) 2026-05-25 (월) → 5월의 4번째 월요일 → 4주차
```

### 7-2. 전주 Notion 페이지 수집

Notion 상위 페이지(`3643e986-a942-812e-b4e9-dca08f857e86`) 하위에서
**전주 월요일 ~ 금요일** 날짜에 해당하는 일일 브리핑 페이지를 `notion-fetch`로 읽는다.

- 대상 페이지 형식: `YYYY.MM.DD (요일)`
- 읽어야 할 요일: 월·화·수·목·금 (5개, 없으면 해당 날짜 건너뜀)
- 각 페이지의 P1·P2 항목, 액션 아이템, P3·P4 표를 추출

### 7-3. 주간 요약 페이지 생성

- **위치**: 상위 페이지 `3643e986-a942-812e-b4e9-dca08f857e86` 하위 (일일 브리핑과 동일)
- **제목**: `MM월 N주차 이메일 브리핑` — 예: `5월 4주차 이메일 브리핑`
- **아이콘**: 📊
