# 반도체 장비 PDM/PLM 시스템 구축서
## Google Cloud 기반 · Claude Code 활용 · 버전관리 통합 (DWG 전용 · 서버리스)

> **작성일:** 2026-05-25  
> **대상 환경:** 반도체 장비(Chiller, Wafer Chuck 등) 기계 설계  
> **목적:** 지속적 개발 및 디자인 구축, 버전관리 기반 앱/웹사이트 최종 배포

> **설계 전제 (확정):**
> 1. **DWG 전용** 업로드 (소용량) → Docker 미사용, 서버리스(Cloud Functions + Firebase Hosting)
> 2. **이중키 모델** → `dwgNo`(도번)가 유일키, `itemCode`(품목코드)는 중복 허용 그룹키
> 3. **검색 + APS 뷰어** → Item Code/dwg no. 검색 후 Autodesk APS(Forge) 웹 뷰어로 DWG 열람
> 4. **등각뷰(3D) 이미지** → 현재 제외 (스키마 optional 필드만 예약, 추후 확장)
> 5. **승인** → 담당자(여러 명) 제출 → **검토자 2명 전원 승인** 시 Released
> 6. **계정** → **관리자가 1회 발급** (자가 가입 없음)

## 시스템 핵심 개요

### 해결 과제
반도체 장비 설계 환경에서 발생하는 문제:
- 도면 버전 혼재 → 구형 도면으로 부품 제작 사고
- 한 제품에 여러 도면(조립도/상세도) → 품목코드·도번 구분 체계 부재
- 승인 프로세스 불투명 → 미승인 도면 유출
- 분산된 파일 관리 → 중복 설계, 재작업 낭비

### 핵심 해결 방향

```
[설계자 CAD 작업 (DWG)]
       ↓
[도면 업로드 (DWG 단일)]
       ↓
[자동 채번: itemCode(중복 허용) + dwgNo(유일) + Revision]
       ↓
[APS 변환 → 웹 뷰어 열람]
       ↓
[승인 워크플로우: 담당자 제출 → 검토자 2명 전원 승인 → Released]
       ↓
[BOM 연계 + 전 부서 알림]
       ↓
[Cloud Storage 영구 보관]
```

### 기술 스택 요약

| 레이어 | 기술 | 역할 |
|--------|------|------|
| Frontend | Next.js 14 + Tailwind CSS | 대시보드, 검색, DWG 뷰어, 승인 UI |
| Backend | Node.js + Express (Cloud Functions 2nd gen 진입점) | REST API, 비즈니스 로직 |
| Database | Firestore (NoSQL) | items/drawings/BOM 메타데이터 |
| Storage | Cloud Storage | DWG 도면 파일 (소용량) |
| DWG 뷰어 | Autodesk APS (Forge) Model Derivative + Viewer | DWG 웹 열람 |
| Auth | Firebase Authentication | 역할 기반 접근 제어 (관리자 1회 발급) |
| Functions | Cloud Functions v2 | HTTP API + 이벤트 트리거 + 자동화 |
| Deploy | Cloud Functions + Firebase Hosting | **Docker 미사용** 서버리스 배포 |
| IaC | Terraform (선택) | 인프라 코드화 |
| CI/CD | Firebase CLI + GitHub Actions | 자동 빌드/배포 |
| AI | Claude Code (Anthropic API) | 설계 지원, 코드 생성 |
