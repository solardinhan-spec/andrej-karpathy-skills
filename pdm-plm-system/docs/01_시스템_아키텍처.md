## 1.2 데이터 모델 설계 (이중키: itemCode + dwgNo)

> **핵심 원칙:** 한 제품(품목)은 여러 도면을 가질 수 있다.
> - `itemCode`(품목코드)는 **제품을 식별** — 동일 제품의 여러 도면이 같은 값을 **중복** 공유
> - `dwgNo`(도번)는 **도면 문서를 식별** — 전역 **유일키(PK)**
> - 따라서 `drawings` 컬렉션의 **문서 ID = dwgNo**, `itemCode`는 그룹핑 필드

### Firestore 컬렉션 구조

```
firestore/
├── sequences/                    # 자동 채번 카운터
│   ├── ITEM_CH → { currentSeq: 42 }   # 품목코드 Chiller 계열
│   ├── ITEM_WC → { currentSeq: 15 }   # 품목코드 Wafer Chuck 계열
│   └── DWG     → { currentSeq: 1024 } # 전역 도번 시퀀스 (유일)
│
├── items/                        # 품목(제품) 마스터 — itemCode 유일
│   └── CH-001/
│       ├── itemCode: "CH-001"
│       ├── name: "냉각수 배관 어셈블리"
│       ├── category: "Chiller"
│       ├── material: "SUS316L"
│       ├── weight: 2.4
│       ├── latestRev: "C"        # 대표 도면의 최신 리비전 캐시
│       ├── drawingCount: 3       # 이 품목에 연결된 도면 수
│       ├── createdBy: "uid_xxx"
│       └── createdAt: timestamp
│
├── drawings/                     # 도면 문서 — dwgNo 유일키(PK), 불변 이력
│   ├── DWG-0001/                 # 같은 itemCode를 가진 여러 도면 가능
│   │   ├── dwgNo: "DWG-0001"
│   │   ├── itemCode: "CH-001"    # 그룹키 (중복 허용)
│   │   ├── title: "조립도"
│   │   ├── revision: "C"
│   │   ├── status: "Released"    # In Work | In Review | Released | Obsolete
│   │   ├── filePath: "drawings/DWG-0001/REV_C/..."
│   │   ├── fileUrl: "gs://..."

│   │   ├── apsStatus: "complete"  # pending | inprogress | complete | failed

│   │   ├── reviewers: ["uid_r1","uid_r2"]   # 검토자 정확히 2명

│   │   │     "uid_r1": { approved: true, at: timestamp },
│   │   │     "uid_r2": { approved: true, at: timestamp }
│   │   │   }
│   │   ├── changeReason: "치수 수정"
│   │   ├── uploadedBy: "uid_a"
│   │   ├── uploadedAt: timestamp
│   │   └── revisions/          # 서브컬렉션: 리비전 불변 이력
│   │       ├── A/ → { status:"Obsolete", filePath, approvals, uploadedAt }
│   │       ├── B/ → { status:"Obsolete", ... }
│   │       └── C/ → { status:"Released", ... }   # 현재 리비전
│   ├── DWG-0002/ → { itemCode: "CH-001", title: "상세도 #1" }
```

## 1.3 도면 상태 전이도 (검토자 2명 전원 승인)

```
        [신규 도면 등록]
             │
             ▼
        ┌─────────┐
        │ In Work │◄──────────────────┐
        └────┬────┘                   │
             │ 담당자 제출 (검토자 2명 지정)│ ECO/변경 시작
             ▼                        │ (신규 Rev)
        ┌──────────┐                  │
        │ In Review│                  │
        └────┬─────┘                  │
             │                        │
       ┌─────┴───────┐                │
       ▼             ▼                │
  검토자1 승인     검토자2 승인          │
       │             │                │
       └──────┬──────┘                │
              │ ※ 2명 모두 승인 시에만   │
              ▼                        │
        ┌─────────┐                   │
        │Released │──────────────────►┘
        └────┬────┘
             │ 동일 itemCode·동일 도번의 신규 Rev 배포 시
             ▼
        ┌──────────┐
        │ Obsolete │ (영구 보존, 조회만 가능)
        └──────────┘
```

> **부분 승인 처리:** 검토자 1명만 승인하면 `approvals`에 기록되지만 상태는 **In Review 유지**.
> 2명의 `approved`가 모두 `true`가 되는 순간에만 `Released`로 전환된다.

## 1.4 채번 규칙

### 품목코드 (itemCode) — 중복 허용 그룹키
| 단계 | 예시 | 설명 |
|------|------|------|
| 신규 제품 | `CH-001` | 분류 Prefix(CH) + 시퀀스 |
| 동일 제품 추가 도면 | `CH-001` 재사용 | 기존 itemCode 그대로 입력(중복) |

### 도번 (dwgNo) — 전역 유일키
| 단계 | 예시 | 설명 |
|------|------|------|
| 도면 등록 | `DWG-0001` | 전역 시퀀스, 트랜잭션으로 유일성 보장 |
| 다음 도면 | `DWG-0002` | 품목과 무관하게 단조 증가 |

### Revision — dwgNo별 자동 증가
| 단계 | 리비전 | 설명 |
|------|--------|------|
| 초기 | A | 도면 최초 등록 |
| 변경 | B, C ... | Released 상태에서 재업로드 시 +1 |
| Z 이후 | AA, AB ... | 알파벳 조합 확장 |

> **분류 Prefix:** `CH`=Chiller, `WC`=Wafer Chuck, `AS`=Assembly, `EL`=Electrical

## 1.5 검색 → DWG 열람 흐름

```
[검색창] Item Code 또는 dwg no. 입력
       ↓
[Search API] items / drawings 조회
   - itemCode로 검색 → 해당 품목의 모든 도면 목록
   - dwgNo로 검색 → 단일 도면
       ↓
[결과 목록] dwgNo · itemCode · title · revision · status
       ↓
[열람 클릭] drawings/{dwgNo}.apsUrn 사용
       ↓
[APS Viewer] 브라우저에서 DWG 렌더링 (다운로드 불필요)
```

## 1.6 DWG 변환 파이프라인 (APS)

```
설계자 DWG 업로드
       ↓
Cloud Functions: Cloud Storage 저장 (drawings/{dwgNo}/REV_{rev}/*.dwg)
       ↓
APS OAuth2 토큰 발급 (client id/secret @ Secret Manager)
       ↓
APS OSS 버킷에 DWG 업로드
       ↓
Model Derivative 변환 잡 등록 (DWG → SVF2)
       ↓
apsUrn 저장 (apsStatus: pending → inprogress → complete)
       ↓
프론트엔드 APS Viewer가 apsUrn으로 렌더링
```

```

```
