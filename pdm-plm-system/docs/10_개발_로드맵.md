# 10. 개발 로드맵 (Phase별 계획)

## 전체 로드맵 개요

```
Phase 1 (1~2개월)   Phase 2 (3~4개월)   Phase 3 (5~6개월)   Phase 4 (7~12개월)
─────────────────   ─────────────────   ─────────────────   ─────────────────
PDM 핵심 기능        PLM 확장 기능        고급 자동화           외부 시스템 연동

승인 워크플로우       품질 관리(QC)        ML 이상 감지          IoT 센서 연동
```

## Phase 1: PDM 핵심 구축 (MVP, DWG 전용·서버리스)

**목표:** DWG 도면 관리, 리비전 이력, 검토자 2명 승인 워크플로우의 기본 동작

### Sprint 1 (2주)
- [ ] GCP 프로젝트 초기화 (Firestore, Storage, Cloud Functions — Docker 미사용)
- [ ] Firebase Authentication 설정 + 관리자 1회 계정 발급 API (자가 가입 차단)
- [ ] 부트스트랩 admin 계정 생성 (scripts/bootstrap_admin.js)
- [ ] 품목(itemCode) 등록 + 도번(dwgNo) 자동 채번
- [ ] 기본 UI 프레임워크 (Next.js + Tailwind) + 로그인 화면

### Sprint 2 (2주)
- [ ] DWG 단일 업로드 API (Cloud Storage 저장, 32MB 제한)
- [ ] APS(Forge) 변환 잡 등록 + apsUrn 저장
- [ ] Revision 자동 관리 (dwgNo별 A → B → ... → AA), revisions 서브컬렉션
- [ ] 검색 화면 (Item Code / dwg no.) + 결과 목록

### Sprint 3 (2주)
- [ ] APS Viewer 컴포넌트 (검색 → DWG 웹 열람)
- [ ] BOM 등록 및 계층 전개 API (itemCode 단위, 재귀 DFS)
- [ ] BOM 트리 뷰어 컴포넌트 (접기/펼치기)
- [ ] Firestore Security Rules 적용 (상태 전환은 백엔드 전용)

### Sprint 4 (2주)
- [ ] 검토자 2명 전원 승인 워크플로우 (제출 → 부분 승인 → Released)
- [ ] 리비전 최근 내역 화면
- [ ] Cloud Functions 트리거 (배포 시 담당자/검토자 Gmail 알림)
- [ ] Firebase Hosting + Functions 배포 파이프라인

**Phase 1 완료 기준:**
- 동일 itemCode로 여러 dwgNo 도면 등록 가능 (중복 품목코드 확인)
- DWG 업로드 → APS 변환 → 웹 뷰어 열람 동작
- Revision A/B/C 순차 관리 + 리비전 내역 조회
- 검토자 2명 모두 승인 시에만 Released 전환 (1명 승인 시 In Review 유지)
- Item Code/dwg no. 검색 동작
- 관리자만 계정 발급, 자가 가입 불가 확인

## Phase 3: 고급 자동화 (AI + 자동화)

**목표:** Claude Code AI를 활용한 설계 자동화 및 원가 최적화

### Claude API 연동 기능

```javascript
// Claude API를 이용한 설계 변경 영향 분석
const Anthropic = require('@anthropic-ai/sdk');

const client = new Anthropic();

async function analyzeChangeImpact(changedPartNo, changeDescription, affectedBoms) {
  const message = await client.messages.create({
    model: 'claude-opus-4-7',
    max_tokens: 1024,
    messages: [
      {
        role: 'user',
        content: `
          반도체 장비 PDM 시스템에서 설계 변경 영향 분석을 수행해 주세요.

          변경 품번: ${changedPartNo}
          변경 내용: ${changeDescription}
          영향받는 상위 어셈블리: ${affectedBoms.join(', ')}

          다음을 분석해 주세요:
          1. 기능적 영향 범위
          2. 인접 부품 재검토 필요 여부
          3. 재고 처리 권고사항
          4. 예상 리스크 수준 (Low/Medium/High)
        `
      }
    ]
  });

  return message.content[0].text;
}
```

### 자동화 기능 목록
- [ ] AI 기반 설계 변경 영향 분석 (Claude API)
- [ ] BOM 중량/원가 자동 산출
- [ ] 도면 OCR → 자동 메타데이터 추출 (Vision AI)
- [ ] 유사 부품 중복 감지 (임베딩 유사도)
- [ ] 설계 검토 체크리스트 자동 생성

## 개발 환경 설정 빠른 시작

```bash
# 1. 저장소 클론
git clone https://github.com/your-org/pdm-plm-system.git
cd pdm-plm-system

# 2. 백엔드(Functions) 설정
cd pdm-functions
npm install
cp .env.example .env.local
# .env.local에 Firebase 서비스 계정 키 경로 + APS 키 설정

# 3. 프론트엔드 설정
cd ../pdm-dashboard
npm install
cp .env.example .env.local
# .env.local에 Firebase 클라이언트 키 설정

# 4. Firebase 에뮬레이터로 로컬 테스트 (Docker 불필요)
npm install -g firebase-tools
firebase emulators:start --only firestore,storage,auth,functions

# 5. 프론트엔드 개발 서버 실행
cd pdm-dashboard && npm run dev  # http://localhost:3000
```
