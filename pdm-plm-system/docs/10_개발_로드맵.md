# 10. 개발 로드맵 (Phase별 계획)

## 전체 로드맵 개요

```
Phase 1 (1~2개월)   Phase 2 (3~4개월)   Phase 3 (5~6개월)   Phase 4 (7~12개월)
─────────────────   ─────────────────   ─────────────────   ─────────────────
PDM 핵심 기능        PLM 확장 기능        고급 자동화           외부 시스템 연동
Part 등록/채번       라이프사이클 관리     AI 설계 지원          ERP 연동
도면 Revision        ECN/ECO 워크플로우   BOM 자동 생성         3D CAD 뷰어
BOM 구조             공급망 관리          원가 자동 산출         모바일 앱
승인 워크플로우       품질 관리(QC)        ML 이상 감지          IoT 센서 연동
```

## Phase 1: PDM 핵심 구축 (MVP)

**목표:** 도면 관리, 버전 이력, 승인 워크플로우의 기본 동작

### Sprint 1 (2주)
- [ ] GCP 프로젝트 초기화 (Firestore, Storage, Cloud Run)
- [ ] Firebase Authentication 설정 (역할: admin, designer, viewer)
- [ ] Part 등록 API (자동 채번 - CH, WC, AS 접두사)
- [ ] 기본 UI 프레임워크 (Next.js + Tailwind)

### Sprint 2 (2주)
- [ ] 도면 업로드 API (PDF + STEP, Cloud Storage 저장)
- [ ] Revision 자동 관리 (A → B → ... → Z → AA)
- [ ] 도면 상태 전환 (In Work → Released → Obsolete)
- [ ] 대시보드 UI (품목 목록, 상태 배지)

### Sprint 3 (2주)
- [ ] BOM 등록 및 계층 전개 API (재귀 DFS)
- [ ] BOM 트리 뷰어 컴포넌트 (접기/펼치기)
- [ ] Firestore Security Rules 적용
- [ ] 도면 다운로드 Signed URL

### Sprint 4 (2주)
- [ ] 승인 워크플로우 UI (승인 버튼, 확인 모달)
- [ ] Cloud Functions 트리거 (승인 시 Gmail 알림)
- [ ] 도면 이력 조회 페이지
- [ ] Docker + Cloud Run 배포 파이프라인

**Phase 1 완료 기준:**
- 품번 자동 채번 및 도면 업로드 동작
- Revision A/B/C 순차 관리 확인
- 승인 버튼 클릭 → Released 상태 전환 + 알림 수신
- BOM 3단계 계층 정상 전개

## Phase 3: 고급 자동화 (AI + 자동화)

**목표:** Claude Code AI를 활용한 설계 자동화 및 원가 최적화

### Claude API 연동 기능

```javascript
// Claude API를 이용한 설계 변경 영향 분석
const Anthropic = require('@anthropic-ai/sdk');

const client = new Anthropic();

async function analyzeChangeImpact(changedPartNo, changeDescription, affectedBoms) {
  const message = await client.messages.create({
    model: 'claude-opus-4-7',
    max_tokens: 1024,
    messages: [
      {
        role: 'user',
        content: `
          반도체 장비 PDM 시스템에서 설계 변경 영향 분석을 수행해 주세요.

          변경 품번: ${changedPartNo}
          변경 내용: ${changeDescription}
          영향받는 상위 어셈블리: ${affectedBoms.join(', ')}

          다음을 분석해 주세요:
          1. 기능적 영향 범위
          2. 인접 부품 재검토 필요 여부
          3. 재고 처리 권고사항
          4. 예상 리스크 수준 (Low/Medium/High)
        `
      }
    ]
  });

  return message.content[0].text;
}
```

### 자동화 기능 목록
- [ ] AI 기반 설계 변경 영향 분석 (Claude API)
- [ ] BOM 중량/원가 자동 산출
- [ ] 도면 OCR → 자동 메타데이터 추출 (Vision AI)
- [ ] 유사 부품 중복 감지 (임베딩 유사도)
- [ ] 설계 검토 체크리스트 자동 생성

## 개발 환경 설정 빠른 시작

```bash
# 1. 저장소 클론
git clone https://github.com/your-org/pdm-plm-system.git
cd pdm-plm-system

# 2. 백엔드 설정
cd pdm-server
npm install
cp .env.example .env.local
# .env.local에 Firebase 서비스 계정 키 경로 설정

# 3. 프론트엔드 설정
cd ../pdm-dashboard
npm install
cp .env.example .env.local
# .env.local에 Firebase 클라이언트 키 설정

# 4. Firebase 에뮬레이터로 로컬 테스트
npm install -g firebase-tools
firebase emulators:start --only firestore,storage,auth,functions

# 5. 개발 서버 실행
cd pdm-server && npm run dev     # :3000
cd pdm-dashboard && npm run dev  # :3001
```
